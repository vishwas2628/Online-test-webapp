# 10. Database Design and Collections

The **Online Test Taking Web Application** leverages **MongoDB**, a NoSQL document-oriented database, to store and manage application data. This choice allows for a flexible and scalable data model, particularly suitable for handling the nested structures of examination papers and diverse question formats.

The database is architected around three primary collections: **Users**, **Tests**, and **TestAttempts**.

## 10.1 Users Collection
This collection is the central repository for all user entities in the system. It handles authentication credentials and role-based access control (RBAC).

*   **primary_key (_id):** Unique Object ID automatically generated by MongoDB.
*   **name (String):** The full name of the user (Student or Teacher).
*   **email (String):** The user's unique email address. This field is indexed to ensure no duplicate registrations occur.
*   **password (String):** A secure, hashed string (using BCrypt) of the user's password. Raw passwords are never stored.
*   **role (String):** A discriminator field (enum: `'student'`, `'teacher'`) that determines the user's access privileges within the application.
*   **createdAt (Date):** Timestamp of account creation.

## 10.2 Tests Collection
The Tests collection is the core of the examination content. It stores the metadata for the exam as well as the actual question payload.

*   **teacherId (ObjectId):** A reference to the **User** who created the test. This linkage ensures only the creator can edit or delete the test.
*   **title (String):** The descriptive title of the examination (e.g., "CS101 Final Exam").
*   **status (String):** Lifecycle management field (e.g., `'draft'`, `'published'`, `'closed'`).
*   **duration (Number):** The total time allocated for the test in minutes.
*   **questions (Array of Objects):** An embedded array where each object represents a single question:
    *   `questionText`: The actual question content.
    *   `options`: Array of possible answer strings.
    *   `correctAnswer`: The index or value of the correct option (hidden from students).
    *   `marks`: Positive marks for a correct answer.
*   **schedule (Object):** Contains `startTime` and `endTime` fields to strictly control the window of availability for the exam.

## 10.3 TestAttempts Collection
This collection records the transactional data of students taking exams. It serves as the bridge between a **Student** and a **Test**.

*   **studentId (ObjectId):** A reference to the **User** (Student) who took the test.
*   **testId (ObjectId):** A reference to the **Test** that was attempted.
*   **answers (Array):** Stores the student's submitted responses. This is an array of objects mapping `questionId` to the `selectedOption`.
*   **score (Number):** The final calculated score, populated automatically by the grading engine upon submission.
*   **submittedAt (Date):** The precise timestamp when the student finalized the exam.

## 10.4 Data Relationships
Although MongoDB is non-relational, we establish logical relationships via references:
*   **One-to-Many:** One Teacher can create multiple Tests.
*   **Many-to-Many:** One Student can attempt multiple Tests, and one Test can be attempted by multiple Students (facilitated by the `TestAttempts` collection).

These collections are optimized with appropriate indexes on `email`, `teacherId`, and `studentId` to ensure query performance remains instantaneous even as the dataset grows.
